01/The transpiler is solved. Trust isn't.

You have a legacy C codebase. You want it in Rust — memory safety, modern toolchain, crates ecosystem.

So you run a C-to-Rust converter. It outputs thousands of lines. Now the real questions start: Does it compile? What did it hide? How much unsafe came across? Which symbols didn't resolve? Who reviews 40,000 mechanical lines against the original?

Most teams answer by not migrating. The converter's output lands in a folder, gets skimmed once, and dies there. The bottleneck was never translation — it's verification.

02/Ship the evidence, not just the code

c2proof wraps the c2rust engine behind gates that refuse bad input and artifacts that expose output.

GATEFlat-scan refusal before any work runs. Subdirectories, Makefiles, non-C files → rejected with the exact reason, exit code 2. No wasted compute on repos v0 can't handle honestly.
PINc2rust 0.20.0, containerized, immutable. The runner image lives on GHCR, built from one pinned Dockerfile. Upstream churn cannot silently change your output.
GATEOutput must survive clippy. Every port faces cargo clippy -- -D warnings. Findings are captured into the report, never hidden.
PROOFREPORT.md rides inside the PR. Build status, clippy warning count, per-file unsafe fn table. Reviewers read evidence first, diff second.

The label is permanent: this is mechanical translation, labeled as such everywhere it appears. No safe-Rust promises. That honesty is the product.

03/Pipeline

Five stages. Each one either advances the port or stops everything with a printed reason.

  1. 01  clone — shallow-clone the target repo, or run against a local path.
  2. 02  scan — flat .c/.h only. Anything else → refused: reason, exit 2.
  3. 03  transpile — pinned c2rust container from GHCR, or offline golden fixture.
  4. 04  verify — clippy gate runs; status and unsafe-fn counts collected for REPORT.md.
  5. 05  publish — branch push + PR with REPORT.md committed inside it.

--fixtureNo Docker on your machine? c2proof migrate ./tinyexpr --fixture replays a CI-generated golden fixture through the full pipeline — gates, verification, report, all offline.

06/FAQ

Is the generated Rust safe?
No. It is mechanical c2rust translation and contains unsafe blocks. The report counts them per file. Safe-Rust refactoring is a later, separate step.
What C projects are supported?
Flat directories of .c/.h files with no build system. Anything else is refused up front with exit code 2 and a printed reason. Makefile/cmake parsing is on the roadmap, not shipped.
Do I need Docker installed?
Only for real transpilation runs. Use --fixture mode for a fully offline pipeline against a CI-generated golden fixture.
How much does it cost?
Nothing. MIT licensed, zero-cost stack: Rust toolchain, pinned c2rust container, GitHub Actions free tier. No accounts, no tiers, no telemetry.
Which converter does it use?
c2rust, version-pinned at 0.20.0 inside an immutable GHCR image. The pin exists so upstream releases cannot silently change your migration output.
Can I trust the verification report?
It is generated from cargo clippy and source scans on every run — never written by hand. Its limits are labeled in the file itself: regex-level unsafe counting, no formal proofs.
What's on the roadmap?
v0.2 adds a test-parity oracle that runs original C tests against the port. Later: agent-generated ports as input, LLM refactor passes gated by tests.
